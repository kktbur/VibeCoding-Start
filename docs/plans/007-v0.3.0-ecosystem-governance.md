# Plan 007: VibeCoding Start v0.3.0 Ecosystem and Governance

- Status: COMPLETED — v0.3.0 released; G9 observation is open
- Date: 2026-09-05
- Baseline: public `v0.2.0` Release at merge commit `994b121e1cff0b7eb514ce03ea79b83766d28c28`
- Trigger: The owner explicitly requested continuation after confirming that `v0.2.0` was published; this plan does not claim external user feedback.

## Goal

Complete the v0.3.0 ecosystem and governance surface from the original roadmap so a Chinese-speaking user, contributor, or security reporter can enter the repository without relying on hidden chat history.

## Work packages

- WP-31: add `README.zh-CN.md` for user-facing Why, installation, privacy, examples, contribution links, and license guidance. Keep the English README and the English `standard-v1.3.md` as canonical normative sources.
- WP-32: add `CONTRIBUTING.md`, a `scripts/check.sh` wrapper for the existing standard-library checks, bug/Skill-behavior/documentation Issue templates, and `.github/PULL_REQUEST_TEMPLATE.md`. Name the required CI workflows and keep the independent-review requirement explicit.
- WP-33: add `SECURITY.md` with the private reporting boundary, secret-handling rules, and a link to the privacy guidance.
- WP-35: dogfood the repository's own governance entry points, close the v0.2.0 release questions, and refresh the indexed state, changelog, and rollback record.

WP-34, removal of the version from the `standard-v1.3.md` filename, is intentionally deferred to a separate PR. This plan does not duplicate or rewrite the normative standard.

## Acceptance

- `README.zh-CN.md` exists, is linked from the English README, and states that the English standard is normative.
- The English README remains English-first, links the Chinese user-facing README, and pins installation to the published `v0.3.0` release while keeping `main` as an explicitly separate development path.
- `CONTRIBUTING.md` documents the read order, exact local verification commands, independent review expectation, PR traceability, rollback, and privacy boundary.
- `scripts/check.sh` runs the same repository checks on Unix-like shells without installing third-party dependencies; the Windows path remains explicit PowerShell 7.
- The three Issue templates and PR template request safe, reproducible evidence and do not ask contributors to paste raw `.project-memory` records.
- `SECURITY.md` explains that the Plugin does not intentionally upload project memory and gives a private reporting route without inventing a maintainer email address.
- Deterministic governance checks validate the required files, links, language switch, English normative-standard statement, template set, and secret/privacy boundary.
- A fresh empty-project `$vibecoding-start` E2E is completed before a v0.3.0 Release is claimed; if the host runner is unavailable, the failure and recovery path remain explicit.
- The indexed project documents record the released `v0.3.0` baseline, its `v0.2.0` rollback package, and the open G9 observation phase.
- Existing package, document, link, freshness, example, version, line-ending, name-drift, and compilation checks remain green.

## Explicit non-goals

Do not add databases, vector search, runtime orchestration, message buses, task queues, MCP/App dependencies, Docker testing, clean-room install matrices, release automation, a CLA, or a second Skill source. Do not rewrite public history, translate the entire standard, or rename the standard file in this candidate.
