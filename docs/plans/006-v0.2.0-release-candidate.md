# Plan 006: VibeCoding Start v0.2.0 Release Candidate

- Status: ACTIVE — PR #5 open for owner review; merge/tag/Release checkpoints remain pending
- Date: 2026-09-05
- Baseline: public `main` after [PR #4](https://github.com/kktbur/VibeCoding-Start/pull/4), with `v0.1.1` retained as the last released package
- Trigger: The owner explicitly requested continuation; this plan does not claim external user feedback.

## Goal

Finish the remaining v0.2.0 usability work from the original improvement roadmap, then prepare a reviewable release candidate without changing the frozen `v0.1.1` tag.

## Work packages

- WP-21: add a concrete Small/Medium/Large gate-depth matrix and Small-project hard constraints to the main Skill.
- WP-24: make ownership and references between the main Skill, project-knowledge Skill, scaling rules, standard, and README explicit and testable.
- RC-01: set the Plugin manifest and changelog to `0.2.0`, update the indexed project state, and record the release/rollback boundary.

## Acceptance

- The main Skill contains the ten-gate depth matrix and the Small-project skeleton/no-empty-directory constraints.
- The public `docs/examples/small-project/project/` example acts as the valid-small-project fixture: all seven required files remain short and no empty governance directories are introduced; the contract test covers every G0-G9 row.
- `scaling-rules.md` gives concrete Small-project artifact minimums and does not contradict the main Skill.
- The companion Skill states that it owns `INIT`/`UPDATE`/`AUDIT`, while the main Skill owns G0-G9.
- Deterministic checks cover the Small-path contract and all existing package/document checks remain green.
- `plugin.json` reports `0.2.0` and the newest dated changelog entry is `[0.2.0]`.
- The public README remains English-first/Chinese-second and continues to pin the last existing stable tag until a `v0.2.0` tag is actually created.
- The `v0.1.1` tag remains unchanged and is the rollback package until the new tag and Release are independently verified.

## Explicit non-goals

Do not add runtime orchestration, a message bus, task queue, vector store, MCP/App dependency, Docker testing, clean-room matrices, release automation, or a second Skill source. Do not claim external user feedback or a published `v0.2.0` before the tag and Release exist.

## Release and rollback

This branch prepares the package and release notes. Merge, tag, GitHub Release, and tag-triggered CI are separate checkpoints. Until `v0.2.0` is publicly tagged and verified, keep the README's pinned install path on `v0.1.1`. If the candidate is rejected, revert the release-candidate PR and retain `v0.1.1` as the last-known-good package.
